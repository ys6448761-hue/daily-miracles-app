# REPORT — WishArt V4 Architecture

## 0. 현재 GPTS 구조 개요

Original은 두 개의 블록으로 구성되어 있다.

1. **"DreamTown Core SSOT v4.0 추가 규칙"** — Reveal Rule 최상위 규칙, 1P/2P/3P 정의, 별씨앗 규칙 v1, 별공방 Reveal Rule, 미남크루즈 감정 항로 시스템, QR/참여순서 규칙, DreamTown 최종 3막 구조.
2. **"DreamTown 소원그림 SSOT v3.7 (압축본)"** — 철학, 캔버스, 보석별&장소매핑, 미남크루즈 오리진(비주얼), 여수 오리진 묘사, CUT1/CUT2 구조, Identity Lock, 수채화 시그니처, 표정&Kling, 네거티브, QC.

규칙 그룹은 SSOT-WISHART-001의 14개 카테고리(①~⑭)로 재구성했다.

---

## 1. V4에서 그대로 유지해야 하는 규칙

- Reveal Rule 순서: 보석별 → 별씨앗 → 별공방, 3P 이전 등장 절대 금지
- Identity Lock 수치(유지 80~90%, 나이 -5~10세, V라인/눈확대 금지)
- Gem Star 5종 매핑(치유=Emerald/오동도, 새출발=Diamond/엑스포역, 용기=Ruby/케이블카, 지혜=Sapphire/하멜등대, 감사=Citrine/이순신광장)
- 별 크기 5% 이하 규칙
- CUT1/CUT2 인물 비율(45~55% / 30~40%)과 응답 순서(별→하늘→구름→노을→바다→꽃→나무→사람)
- 캔버스 9:16, 상단75%/하단25% 규칙
- 미남크루즈 오리진 8대 필수 요소와 우선순위
- 네거티브 프롬프트 전체(이미지·Kling)
- QC 5문항, 출고 기준(S급/A급), 3·2·1 멈춤 규칙
- 별씨앗 실물 제품 규격(노란색 야광, 5각, 반투명, 텍스트 금지)
- 금지어(사주/점술/운세/팔자/궁합), 3D CGI 얼굴 금지

이 규칙들은 서로 다른 두 블록에서도 일관되게 나타나며 내적 모순이 없어, 수정 없이 SSOT에 그대로 반영했다.

## 2. 중복되어 통합 가능한 규칙

| 중복 내용 | 위치 1 | 위치 2 | 처리 |
|---|---|---|---|
| 3P에서 별공방 최초 등장 | "별공방 Reveal Rule" 절 | "DreamTown 최종 3막 구조" 절 | SSOT §③에서 1회로 통합 |
| 발견→응답→기록 서사 | "DreamTown 공식 서사" | "DreamTown 최종 3막 구조" 결론부 | SSOT §①/②에서 1회로 통합 |
| 하멜등대 시각 묘사(빨강·원통형·방파제 연결) | "Reveal Rule 최상위 규칙"(세로 표기) | "미남크루즈 오리진(LOCKED)"·"여수 오리진 묘사" | SSOT §③/§⑦/§⑩에 각 목적에 맞게 재배치했으나, 원 사실(빨간 원통형 등대·방파제-육지 연결)은 하나의 참조로 통일 가능 |
| 1P/2P/3P 정의 | 최초 상세 정의(등장가능/금지 목록) | "DreamTown 최종 3막 구조"의 압축 재서술 | SSOT §②에서 상세판 기준으로 1회 통합, 압축판은 중복 제거 |
| 미남크루즈 관련 규칙 | "미남크루즈 감정 항로 시스템"(시간대/색감) | "미남크루즈 오리진(LOCKED)"(8대 비주얼 요소) | **완전 중복은 아님** — 하나는 감정/시간 레이어, 하나는 비주얼 구성 레이어. 통합하지 않고 SSOT §⑤(Emotion)/§⑦(Background)에 각각 배치, 상호 참조만 추가 |

## 3. 서로 충돌하는 규칙

1. **버전 번호 불일치** — Original 문서 안에서 "v4.0"(첫 블록 제목), "v3.7"(두 번째 블록 제목), "SSOT-WISHART-v2.1"(문서 최말단 태그) 세 가지 버전 표기가 동시에 존재한다. 어느 것이 실제 최신/확정 버전인지 원문 자체로는 판단할 수 없다. **Code가 임의로 하나를 선택하지 않았다** — 대표 확인 필요.
2. **3P의 핵심 장소 모호성** — v4.0 블록의 Reveal Rule 최상위 규칙은 "3P는 미남크루즈 유람선을... 형태로 표현"이라고 명시하는 반면, 같은 V4 자료 내 다른 절("DreamTown 최종 3막 구조")과 기존 `SSOT-LOC-001`(별도 확정 SSOT)에서는 하멜등대가 "소원/별"의 클라이맥스 장소로 정의되어 있다. **3P(기록/클라이맥스)의 배경이 미남크루즈인지 하멜등대인지, 혹은 두 장소가 순차적으로 모두 쓰이는 것인지 원문만으로는 명확하지 않다.** 임의로 하나를 택하지 않고 SSOT §③/§⑥에 두 서술을 모두 남기되 이 모호성을 명시했다.
3. **1P 등장 가능 목록에 "하멜등대"·"미남크루즈"가 포함**되어 있어, 3P의 "최초 등장"이 정확히 무엇(장소 자체가 아니라 별/별씨앗/별공방이라는 오브젝트)을 가리키는지 원문상 구분이 필요하다. 이는 실제 규칙 충돌이라기보다 **정의 모호성**에 가까우나, 개발 시 혼동 소지가 있어 기록한다.

이 3가지는 SSOT-WISHART-001에서 **Code가 임의로 해석·확정하지 않았다.** 대표 확인 후 반영한다.

## 4. 개선 가능 사항 (참고 제안 — 본문 SSOT에는 포함하지 않음)

> 아래는 새로운 규칙 제안이며, V4 원문에 없는 내용이다. SSOT-WISHART-001 본문에는 포함하지 않고 이 보고서에만 기록한다.

- 4P(참여) 단계를 명시적으로 정의할 것을 제안한다 — 현재 V4는 3막(1P/2P/3P)만 정의하나, 코드(`dreamtown-wishart`)에는 이미 4번째 Act(브랜드/CTA)가 존재해 정합성 확인이 필요하다.
- 기적쇼츠·기적영상·기적스토리북·별빛항로영상·웹툰·애니메이션 각각에 대한 명시적 Product Mapping 규칙 신설을 제안한다.
- "CUT3"의 실제 내용 정의(현재는 이름만 언급됨)를 제안한다.
- `SSOT-BG-001`(Background SSOT)과의 명시적 연동 규칙(현재는 개념적 언급뿐) 신설을 제안한다.
- 버전 넘버링 통일(§3-1의 버전 충돌 해소)을 제안한다.

## 5. Engine 관점에서 재구성한 이유

Original은 GPT가 대화 중 지침을 따르기 위한 자연어 텍스트이며, 같은 규칙이 여러 절에 걸쳐 다른 각도(비주얼/감정/제품)로 반복 서술되어 있다. 개발자가 코드로 옮기려면 "어떤 데이터가 어느 단계에서 필요한가"라는 Engine 관점의 재구성이 필요하다. 이에 따라 SSOT-WISHART-001은 원문의 서술 순서가 아니라 **엔진이 실행되는 순서와 책임(철학→스토리 구조→Reveal→Identity→감정→장소→배경→보석→카메라→프롬프트→네거티브→QC→상품→흐름)** 기준으로 재배열했다. 이 과정에서 원문에 없는 규칙은 추가하지 않았고, 원문에 있으나 모호하거나 상충하는 부분은 위 §3에 그대로 남겨 두었다.
