# REPORT — WishArt V4 Gap Analysis

## 1. 구현 확인됨 (코드와 V4가 일치)

| V4 규칙 | 코드 근거 | 상태 |
|---|---|---|
| Reveal Rule (별/별씨앗/별공방은 3P 이전 금지) | `check_reveal_rule()` — 토큰 스캔으로 1P/2P 프롬프트에 해당 토큰 부재를 검증 | ✅ 구현됨 |
| Camera Rule (2P 사선옆모습, 3P 뒷모습) | 4-Act 구조에서 1P=front_view, 2P=side_view, 3P=back_view | ✅ 구현됨(용어는 다르나 실질적으로 일치) |
| Identity Lock (정체성 보존) | `IDENTITY_MANDATORY` 블록 | ⚠️ **부분 확인** — 코드는 "85~95%" 보존을 명시하나 V4 원문은 "80~90%"다. 수치 범위가 다르다(§4 참조). |
| 나이 역행 금지 | `AGE_MANDATORY` — "do not make the person look decades younger" | ⚠️ **부분 확인** — V4는 "-5~10세 범위 내 허용"인데, 코드가 이 범위를 구체적으로 구현하는지, 아니면 모든 de-aging을 전면 금지하는지는 원문만으로 단정할 수 없다(§4 참조). |
| 미래 예언 금지 | `judge_release()`의 Q9 | ✅ 구현됨 |

## 2. 미구현 (V4에 있으나 코드에 없음, 확인됨)

| V4 규칙 | 상태 |
|---|---|
| 4P(참여) 단계 | V4 원문에는 없으나(§2 원문 확인 사항 참조) **코드에는 오히려 4P Act가 이미 존재**한다 — 이는 "미구현"이 아니라 **"코드가 V4보다 앞서 있다"**는 역방향 간극이다. |
| 기적쇼츠 / 기적영상 / 기적스토리북 / 별빛항로 영상 / 웹툰 / 애니메이션 Product Mapping | V4 원문에도, 코드에도 대응 규칙/구현이 없다(이전 `REPORT-StoryBook_Code_Analysis.md`에서 이미 확인됨). |
| CUT3 구체 정의 | V4 원문에 이름만 언급되고 내용이 없어, 코드에도 대응 구현이 없다. |
| 별씨앗 실물 제품 규격 검수 | 이미지 생성 엔진(prompt_builder.py/image_generator.py)의 범위 밖 — 실물 굿즈 제작 프로세스에서 별도 관리되어야 하나, 그 프로세스 자체가 이번 조사 범위에서 확인되지 않았다. |
| 미남크루즈 감정 항로 시스템(5개 항로별 시간대·색감: 감사=골든아워, 치유=블루아워, 새출발=일출직전, 용기=강렬한석양, 지혜=깊은밤) | 코드의 `WISH_ENGINE`/`LOCATION_MAP`은 5개 Canon 감정을 장소·보석에 매핑하지만, 이 **시간대/색감 팔레트**가 코드에 동일하게 구현되어 있는지는 이전 분석에서 확인되지 않았다. **미확인 — 재확인 필요.** |
| Background Rule의 캔버스 규칙(9:16, 상단75%/하단25%) | `image_generator.py`가 실제로 생성하는 이미지 크기는 `1024x1536`(비율 약 2:3)로 확인되었다 — **V4가 요구하는 9:16(0.5625)과 다른 비율**이다. 명확한 수치 불일치. |

## 3. 미확인 — 코드 재확인 필요 (이전 분석 범위에서 확증되지 않음)

| V4 규칙 | 확인 필요 사항 |
|---|---|
| QC 5문항 vs 코드의 9문항(`evaluation_9q`) | V4는 5개 질문(본인여부/표정/오리진·보석별/캡션없이 구별/안전영역)을 정의하는데, 코드는 `judge_release()`에서 9문항 체계를 쓴다. 1:1 매핑 관계가 확인되지 않았다 — 두 체계가 병존하는지, 5문항이 9문항의 부분집합인지 불명확하다. |
| 이미지 네거티브 프롬프트 토큰 목록(photorealistic, 3D render, CGI, plastic skin 등) | 코드가 정확히 이 토큰 리스트를 사용하는지 이전 분석에서 별도로 확인하지 않았다. |
| 미남크루즈 오리진 8대 필수 요소(보석별/하멜등대/미남크루즈/밤바다/케이블카/돌산대교/꽃/수채화 분위기)가 한 이미지에 동시에 구성되는 로직 | 코드의 장소별 프롬프트 블록은 확인되었으나, "8대 요소 동시 구성"이라는 구체적 컴포지션 규칙의 코드 구현 여부는 미확인. |
| 별공방(Star Workshop) 실제 시각 자산 | 코드가 별/별씨앗과 함께 "별공방" 토큰을 인식·차단하는 것은 확인되었으나(Reveal Rule), 별공방을 실제로 어떻게 시각화하는지(전용 프롬프트 블록 존재 여부)는 미확인. |

## 4. 원문-코드 수치 불일치 (충돌 가능성, 확인 필요)

- Identity Lock 보존율: **V4 원문 "80~90%" vs 코드 "85~95%"** — 범위가 다르다. 어느 쪽이 최신 기준인지 대표 확인 필요.
- 캔버스 비율: **V4 원문 "9:16" vs 코드 실제 출력 "1024x1536(≈2:3)"** — 명확한 불일치.

이 두 항목은 추측으로 해소하지 않았다. `REPORT-WishArt_V4_Architecture.md` §3의 버전 충돌(v4.0/v3.7/v2.1)과 함께, 대표 확인 후 어느 버전/수치를 기준으로 통일할지 결정해야 한다.
