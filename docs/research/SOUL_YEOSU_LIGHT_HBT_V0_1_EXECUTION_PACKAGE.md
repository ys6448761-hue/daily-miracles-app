## 10. Invalid Session Rules

**BLINDING_LEAK:** Participant learns condition identity (A/B) → affected comparison = INVALID. If both comparisons affected → session INVALID.

**WRONG_STIMULUS:** Wrong scenario context shown AND participant read it → affected comparison INVALID (ASSIGN_ERR partial rule from Section 6 applies).

**ASSIGN_ERR:** Wrong 가/나 mapping → Section 6 rules apply.

**INCOMPLETE_Q1:** Participant does not record Q1 Forced Choice AND refuses re-prompt → affected comparison INVALID.

**TECH_FAIL:** Display/recording failure prevents any usable Q1 → affected comparison INVALID.

**Q2 refusal or very short response:** NOT automatically invalid if Q1 is recorded. Record as "[refused]" or "[too brief to code]". Q2 is informational; Q1 is the primary datum.

**Session-level:** INVALID only if BOTH comparisons are invalid. Otherwise PARTIAL_VALID (½ valid count).

**Principle:** Do not discard unfavorable results. Do not silently fix issues after participant has seen stimulus. Do not invalidate sessions merely because preference was unexpected.
